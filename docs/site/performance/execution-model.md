# 并发与串行状态

本页列出截至 2026-11-18 优化工作树的执行状态。区分三件事：**任务运行在哪个线程/进程、任务内部是否并行、多个任务之间是否允许重叠**。实测见 [Y373 线程对照](/performance/benchmarks#y373-全量点云重建-2026-11-18)。

## 状态含义

| 标记 | 含义 |
| --- | --- |
| **内部并行** | 一个任务把独立数据块分配给多个工作线程 |
| **后台串行** | 任务与 GUI 并发，但任务内的项目代码仍按顺序执行 |
| **主线程串行** | 由 GUI/渲染上下文所属线程执行，期间仍可能占用界面时间 |
| **外部引擎** | 项目启动子进程；引擎内部线程数或 GPU 行为由其实现及配置决定 |

不能把 `QThread`、`QProcess`、NumPy 批量操作或异步接口的存在，直接当作“整个算法已经多核并行”的证据。

## 点云、识别与 CAD

| 阶段 | 执行位置 | 当前内部状态 | 限制或依赖 |
| --- | --- | --- | --- |
| GUI 状态、文档版本检查和结果提交 | GUI 主线程 | **主线程串行** | Qt 状态及文档统一提交 |
| 预处理单位转换、体素代表点选择、KD 树构建 | CAD/分析工作线程 | **后台串行** | 本轮未给这些循环增加线程池 |
| 统计离群过滤的逐点 KNN/平均距离 | 同一工作线程及其辅助线程 | **内部并行** | 自动最多 8 线程，小输入退回串行 |
| 离群过滤的均值、方差、中位数/MAD 和阈值 | 工作线程 | **后台串行** | 保留原来的浮点归约顺序 |
| 逐点 PCA、曲率和缺失法向 | 同一工作线程及其辅助线程 | **内部并行** | 每点独立写结果，计数随后汇总 |
| 法向符号的多源最短路径传播 | 工作线程 | **后台串行** | 优先队列和相邻节点更新存在依赖 |
| 独立曲面族 RANSAC | CAD/分析工作线程及其辅助线程 | **按曲面族并行** | 各族使用相同输入、独立的随机流；按原曲面族顺序合并，再拓展平面 |
| 混合曲面族及多尺度残余 RANSAC | CAD/分析工作线程 | **后台串行** | 同一个混合检测和多尺度残余轮次不拆分 |
| 面片连通分量、关系枚举与几何判定 | 分析/关系工作线程 | **后台串行** | 关系推断已移出 GUI，内部未拆分任务 |
| 有限面支撑验证 | CAD/分析工作线程及其辅助线程 | **按面片并行** | 面域构建和参考密度下的复核并行；密度参考、合并与发布保留原顺序 |
| 装配分组、闭合和投影候选搜索 | CAD 工作线程 | **后台串行** | 未建立按零件/候选并行的任务池 |
| 最终 CAD 特征提交与历史重建 | GUI 提交路径 | **主线程串行** | 仍包含原生几何工作，不是只拷贝一个结果指针 |
| 主要 OCCT 布尔运算 | 几何调用所在的线程 | **显式串行** | 主要路径保留 `SetRunParallel(false)` |
| B-Rep 显示三角化、边提取和 VTK 连接 | GUI 显示路径 | **主线程串行** | 当前三角化没有显式开启 OCCT 并行参数 |

预处理中的并行循环并不覆盖全部 KNN 使用处。多尺度恢复、装配邻域和连通分组中的其他查询循环，不能仅因复用了 `KdTree` 就记作已并行。第三方库内部是否自行创建线程，也不能从外层调度表推断；上表描述项目已经明确启用的并行。

### CAD 阶段探针

使用 Release 版 `cad_reconstruction_validation` 回放，并在运行前设置 `PCAD_CAD_PROFILE=1`：

```powershell
$env:PCAD_CAD_PROFILE = '1'
& $engine reconstruct-cloud $cloud $report $step 2> cad-profile.log
Remove-Item Env:PCAD_CAD_PROFILE
```

标准错误实时记录 `PCAD_PROFILE begin/end`。`wall` 是阶段墙钟秒数；`cpu` 是进程所有线程合计 CPU 秒数；Windows 上 `thread_cpu` 是执行探针的线程 CPU 秒数（不可用时为 `-1`）。`cpu / wall` 约等于平均使用的逻辑核数，除以机器逻辑核数才是整机 CPU 百分比。`depth` 是线程内嵌套深度，父阶段已经包含子阶段（包括局部轮廓恢复递归），不能相加。默认不开启探针，不改变重建配置。

识别日志按曲面族记录检测；`support.*` 区分提案索引、面域构建、密度参考、面域复核和结果合并。原始点复验单独记录补证、原始点验证和投回工作点再验证。至少 8192 点的面域会追加邻域、三角化和归属查询子事件；多个面片并发时，子事件墙钟区间可能重叠，其进程 CPU 时间也会重复包含其他线程的工作，不宜直接加总。

## 渲染、拍摄与 Python

| 阶段 | 执行位置 | 当前内部状态 | 说明 |
| --- | --- | --- | --- |
| 相机输入、渲染请求合并和 VTK `Render()` 提交 | 上下文所属 GUI 线程 | **主线程串行** | GPU 执行绘制；同一 RenderWindow 没有交给多个线程同时调用 |
| 预览阴影深度读回、CPU 打包和纹理更新 | GUI 线程 | **主线程串行** | 交互降为 512²，静止/截图恢复 1024² |
| 选择 overlay 更新 | GUI 线程 | **主线程串行** | 减少更新量，没有增加高亮线程池 |
| 点云降采样的读取、融合排序、写盘 | 独立 QThread | **后台串行** | 与 GUI 并发，融合算法本身未多线程化 |
| VTK 结构光逐帧渲染、读回及 PNG 保存 | 上下文所属 GUI 线程 | **主线程串行** | `QTimer` 分帧调度不等于并发渲染；PNG 编码队列尚未实现 |
| Python 结构光重建 | 单个 QProcess 子进程 | **后台进程** | 项目按站点、曝光、图像依次读取和解码 |
| 单站的大点图法向行块 | Python 线程池 | **内部并行** | 最多 4 线程；小图/指定单线程时串行 |
| 三角化分块、站点融合和导出 | Python 子进程 | **项目调度串行** | NumPy 本地计算，未新增站点池或融合任务池 |
| Mitsuba 的站点/曝光/图案循环 | 独立子进程 | **外层串行** | 当前选择 `scalar_rgb`，未启用项目级多帧池或 LLVM/CUDA 切换 |
| COLMAP 各命令阶段 | 独立子进程 | **阶段串行，内部由引擎决定** | 特征、匹配、稀疏、稠密阶段依次推进；CPU/GPU 行为按引擎配置 |

Mitsuba 的 `scalar_rgb` 不能简单等同于“引擎只使用一个 OS 线程”。同样，NumPy/OpenCV 可能在自己的本地算子中使用线程，但这里没有将未测量的库内部行为写成项目新增的并行能力。

## 任务之间如何协调

同一工作区使用 `m_analysisThread`、`m_downsampleThread`、`m_cadTask` 和忙碌状态检查，协调 CAD、曲面分析、关系推断和降采样。它们不会因为“都能后台执行”就同时共享和改写同一份文档。点云有新的编辑时，旧结果依靠版本检查被拒绝；需要的引导重建进入排队流程。

工作线程完成后，经 Qt 队列回到 GUI。主线程检查取消状态、文档版本，以及关系推断的距离/角度容差，再提交结果。关闭工作区时等待线程退出。取消通常在阶段或数据块边界生效，不能中断任意一次已经进入原生库的调用。

## 线程数与串行回退

### C++ 预处理

`preprocessing.conf` 的 `worker_count` 范围为 0–32。`0` 使用硬件并发数和 8 的较小值，`1` 强制串行，其余值指定上限。实际数量还受点数限制：

```text
自动上限 = min(max(1, 硬件并发数), 8)
指定上限 = min(worker_count, 32)
实际工作数 = max(1, min(上限, floor(点数 / 4096)))
```

因此 8192 点以下只有一个工作区间；例如 10,000 点即使指定 8，也只使用两个区间。调用方线程处理其中一个区间，其余区间由辅助线程处理，表中的“8 线程”不是“调用方之外再加 8 个”。

### C++ 曲面验证

`analysis.conf` 的 `support_validation_worker_count` 范围是 0–32。默认 `0` 自动使用最多 8 线程，少于 4096 点时自动串行；`1` 强制串行，其他值指定线程上限，实际受面片数量限制。复跑可设置 `PARAMCAD_ANALYSIS_CONFIG` 指向一份配置副本，只改变这一项。线程数不参与几何缓存签名，也不改变验证阈值。

### C++ 曲面族检测

`analysis.conf` 的 `family_detection_worker_count` 范围是 0–5。默认 `0` 自动使用不超过 CPU 并发数或启用曲面族数的线程，输入少于 4096 点时串行；`1` 强制串行。CGAL 不支持线程的构建回退串行。线程数不参与几何缓存签名；混合检测和多尺度残余恢复不受此选项影响。

对照用 `PARAMCAD_ANALYSIS_CONFIG` 指向配置副本，保持曲面验证线程数和其他选项不变。比较 `detect.independent_families` 的墙钟耗时，而不是相加并行的 `detect.plane` 等子事件。每个检测器有自己的工作数据，并行可能增加峰值内存。

### Python 法向

任一维小于 3、高度不超过 64，或总像素数小于 65,536 时，调用直接计算路径。其余输入按行分块：

```text
每块行数 = max(1, min(64, floor(65536 / 图像宽度)))
工作数 = min(workers 或 CPU 数, 4, 行块数)
```

`workers=1` 为单线程分块，`workers=0` 为自动选择。这里的 `workers` 是法向函数参数，不是 `preprocessing.conf` 的 C++ 设置；当前客户端没有独立的 Python 法向线程数界面。
