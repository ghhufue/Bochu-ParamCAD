# 渲染与交互调优

本轮渲染提速来自减少交互期工作量、重复渲染和大数组更新。VTK/OpenGL 的上下文操作仍在所属 GUI 线程，未使用多线程同时渲染同一视口。

## 当前执行状态

| 工作 | 状态 | 本轮变化 |
| --- | --- | --- |
| 相机输入、渲染提交 | 主线程串行；绘制由 GPU 执行 | 同一事件队列中的重复请求合并 |
| 阴影渲染、深度读回、CPU 打包 | 主线程串行 | 拖动时降低分辨率，结束后恢复 |
| 点云基础颜色与选中高亮 | 主线程串行 | 按版本缓存基础颜色，选中点单独绘制 |
| 点云面显示网格 | 主线程串行 | 按曲面修订缓存，切换集合显示或检查边界时复用 |
| 点云降采样文件读取、融合和写盘 | 后台 QThread，内部串行 | 从 GUI 移走，并校验结果是否过期 |
| 最终点云载入、VTK 上传和 CAD 显示准备 | 仍有主线程工作 | 本轮没有全部移走 |
| 结构光 VTK 渲染和 PNG 保存 | 主线程逐帧串行 | 尚未新增并发编码/写盘队列 |

## 1. 交互期间降低阴影成本

材质预览光源跟随相机。相机移动会使阴影失效，原路径每次都生成 1024² 深度图，读回 CPU、打包为 RGB24，再交给纹理更新。缓存能省掉静止场景的重复工作，但不能消除拖动中的更新。

现在拖动期间使用 512² 阴影。分辨率变化时同步调整阴影相机投影、焦距和 shader 中的尺寸参数，保持投影几何一致。停止交互后，即使已经没有排队渲染请求，也补发完整质量帧；拍摄和截图始终请求 1024²。

| 800×600 长方体视口，40 帧 | 优化前 | 交互优化后 |
| --- | ---: | ---: |
| 帧耗时 p50 | 11.05 ms | 3.04 ms |
| 帧耗时 p95 | 11.83 ms | 3.69 ms |

完整质量路径 p50 为 10.94 ms。交互期间阴影细节有暂时变化，这组数据不能解释为相同阴影质量下的 3.63 倍 GPU 加速。复杂零件仍需单独测量。

## 2. 选中点使用独立图层

原来选中一个点也会遍历全部点，重建颜色数组并标记更新。现在基础颜色按选区文档版本缓存，选中点的位置和颜色交给独立 overlay；只改变选择时，不再重写全部基础颜色。

这降低的是高亮更新量，不是增加并行线程。overlay 不参与拾取，拾取仍返回原始点编号；集合变化会刷新基础颜色，隐藏、清空和重新载入点云也会清理高亮。

截图前隐藏选择 overlay 并恢复源颜色，完成后恢复选区显示。测试检查基础颜色数组不因选择变化而更新，以及点编号、源颜色和可见状态保持正确。

## 3. 合并请求并避免重复 Render

相机输入立即更新姿态，渲染请求在事件循环内合并；相机面板通知已有 50 ms 节流。选择变化也改为请求渲染，减少一次用户动作造成的同步重复绘制。

截图先明确渲染目标姿态和完整质量，再从当前帧读取像素，关闭图像过滤器的自动重渲染。正式结构光 VTK 后端仍保留自己的投影和遮挡参数，不从交互用低分辨率阴影读取测量数据。

## 4. 降采样移到后台

源 PLY 读取、排序融合和原子写盘现在由一个独立 QThread 顺序执行。它与 GUI 并发，但融合排序算法内部仍是串行。

完成时先检查任务是否取消、点云版本是否改变，符合条件才切换活动文件。期间发生集合编辑时，旧结果不覆盖当前点云；恢复原始点云、单位 sidecar 和已有降采样缓存保持原来的行为。最终载入结果和 VTK 连接/上传仍在 GUI 路径，因此不能宣称所有大点云操作都已经无阻塞。

## 5. 复用点云面显示网格

`meshPointCloudSurfaces()` 一次构建所有集合的三角面。`PointCloudActor` 只在曲面修订 `surfaceRevision` 变化时重建：选择点、改变视图或切换集合显示不会重新三角化；拟合、归属或集合编辑才会推进该修订。共面的多个集合先合并网格，再按各自归属拆成独立三角形，避免每个集合重复三角化同一平面。

「交线与边界」和面片交线拟合直接读取这份缓存网格的三角形与顶点，因此检查看到的面域与视口显示一致，不会借用被拒绝的空白区域，也不会为预览再建一份显示网格。边界预览使用独立 renderer 和 actor，关闭后释放。

这条优化减少的是重复 CPU 三角化和 VTK 上传，不是并行渲染。一次曲面编辑仍会使相关网格整体失效；大点云的首次网格构建仍在 GUI 路径执行。

## 验证与后续方向

实际 Qt/VTK 测试覆盖相机输入、拾取编号、高亮、取消、过期结果拒绝和截图姿态。渲染基准还检查非空图像及恢复完整质量后的像素逐字节一致。

GPU 内部直接传递阴影、异步像素读回、PNG 编码队列和显示 LOD 尚未实现。进一步优化前，应分别记录渲染、读回、CPU 打包、纹理更新和编码耗时，避免把 CPU/GPU 同步问题误判为缺少 CPU 线程。
