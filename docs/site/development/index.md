# 开发维护

本栏目面向需要修改、构建、测试或发布 Bochu Capstone 的开发者，说明当前仓库的实际布局、工具链、超参数配置、贡献流程、已经落地的设计决策和后续方向。内容以当前工作树为准，不把历史方案或计划中的接口写成现状。

文档服务三类读者：第一次搭建环境的贡献者、准备调整算法阈值或命令行入口的开发者，以及需要更新站点和发布包的维护者。建议先按下方导航找到对应页面，再回到具体模块页核对数据契约。

## 阅读路径

- 第一次参与开发：先读开发环境与代码布局，再按 [安装与构建](/getting-started/installation) 完成一次客户端构建。
- 只调整算法阈值：直接读超参数配置与 CLI，先确认单位、覆盖顺序和配置校验规则。
- 修改点云到 CAD 的链路：先读 [系统分层与依赖](/architecture/system-layers) 与 [数据契约与坐标约定](/architecture/data-contracts)，再进入对应模块页。
- 准备提交文档：读贡献指南，确认页面注册、链接写法和本地预览步骤。

## 常见开发任务

| 任务 | 先看什么 | 需要同步什么 |
| --- | --- | --- |
| 调整检测、识别或装配阈值 | 超参数配置与 CLI | 源码 `.conf`、对应模块页和验证用例 |
| 新增或修改模块 CLI | 超参数配置与 CLI | `tools/module_cli` 参数、报告字段和 README |
| 修改核心数据结构或修订语义 | 设计决策、系统架构 | 数据契约页、调用方和回归测试 |
| 新增或修改 C++ 测试 | 开发环境与代码布局 | 对应 CMake 目标、CI 命令和验证页 |
| 新增站点页面 | 贡献指南 | `docs/site` 正文与 `docs/.vitepress/config.mts` 的 `sections` 注册 |
| 修改发布内容 | 开发环境与代码布局 | `packaging` 脚本、包内说明和版本号 |

## 维护节奏

- 每次代码改动先确认影响范围：配置键、README 章节、模块页和验证用例是否同时需要更新。
- 文档改动保持小步提交，避免在同一提交中混入无关的格式重排，便于评审和回溯。
- 发布前按路线图核对能力状态，确认页面没有把“开发中”写成“已实现”。

## 文档约定

- **来源优先级**：代码与配置高于 README，README 高于页面描述；不确定的数字、命令和阈值不写入文档。
- **术语统一**：观测快照、源点 ID、曲面证据、有限面片、关系、候选、建模补丁、特征历史、修订、原子提交、B-Rep。
- **路径书写**：文件与目录使用行内代码，例如 `apps/ParamCAD Studio/config/detection.conf`；站内跳转使用以 `/` 开头的绝对路径，不写相对链接。
- **现状边界**：`docs/Outdated/` 只作为历史归档，不作为当前实现依据；第三方二进制 SDK 位于 `deps/`，不递归扫描或提交。
- **同步责任**：改动阈值或行为时，在同一提交中同步配置、README 和本栏目对应页面，避免页面与代码脱节。
- **可验证性**：涉及版本、命令、阈值和字段名的描述应能在仓库内找到出处；无法确认时保留为待核实问题，而不是补全推测。

## 文档边界

本栏目只描述开发与维护流程。具体算法原理见“算法原理”，模块职责与数据契约见“模块手册”和“系统架构”，端到端操作步骤见“快速开始”。当页面与代码不一致时，以当前工作树为准，并在修复代码的同一提交中更新文档。
